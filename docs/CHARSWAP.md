> **Viggle 引擎已于 2026-10-07 移除；H3 原生换人是换人节点唯一的引擎。** 后端拒绝 `engine: "viggle"` 和 `mode: "reference"`；旧画布里的 `swapEngine: viggle` / `swapMode: reference` 会被忽略，按 H3 换人打开。换头（`mode: head`）仍可选，但 H3 路径还没有只换头的做法，现在按换人处理，结果里带说明。
> `comfyui_nodes/third_party/ComfyUI-Viggle-Animate-H3`、`tools/comfyui_setup` 里的条目和 Viggle 权重都留着，现在没有任何节点使用它们。
> 下面从开头到「H3 原生换人 + Character-Swap LoRA」之前，记的是 Viggle 时期的实测，只作历史参考；运行步骤请看「H3 原生换人」一节。

# 换人 / 换头：怎样做才会成功

画布上的 **换人 · H3** 节点把驱动视频里的人换成一张照片里的人。
这份文档记的是 2026-10-04 在一条片子上实测出来的做法，包括哪些做法**不**成立。**只在一条 5 秒片、一个人身上验证过**，
换片换人是否同样成立还不知道；标了"没验证"的地方就是没验证。

## 先记住一条：参考图决定成败（Viggle 时期）

这条路没有提示词，身份只来自参考图，其余全来自驱动视频。参考图和驱动视频差得远（阳光草地的全身照对昏暗室内的背影），
模型就认不出人：换成一个陌生人，衣服碎成三角块或迷彩。**所以不能把照片直接喂 Viggle。**

同一条片子、同一个种子，只换参考图：

| 参考图 | 结果 |
|---|---|
| 阳光全身照，直接用 | 换成另一个人，外套碎成三角块 |
| 驱动视频的一帧，经 Qwen 改成新脸，**提示词写明了帧里的内容和新发型** | 全片 124 帧换成功，外套干净（4 次，含 1 次整条自动流程） |
| 驱动视频的一帧，经 Qwen 改脸，**用通用提示词**（"换成图 2 的脸和发型"） | 外套碎成迷彩（6 次 6 次，不管裁不裁照片、写不写发型） |

通用提示词生成的参考图**看起来也是对的**：Qwen 保留了源片原来的短发和头部朝向，没把头发换掉。写明新发型和画面内容才会真的换。
结果对同一张参考图是确定的（同种子逐帧复现），所以失败了要换的是参考图，不是种子。

## 两种模式

节点接的永远是**原照片**，不用自己做参考图。两种模式都是：后端从驱动视频抽一帧，用 Qwen-Image 2.1 把这一帧改成需要的样子，
再拿改好的这一帧当参考去跑 Viggle。

- **换人**：照片里的人整个换进去，衣服也以照片为准。把照片裁成到腰的大半身像（要看得见衣服），让视觉模型描述帧和照片的
  脸、发型、衣服，Qwen 把这一帧里的人整个换成照片里的人。
  在那条片子上全自动跑通了一次：照片里奶油色挂脖连衣裙、黑发带刘海的女生，换进雨窗边灰外套女人的动作里，全片干净，
  背影时能看到挂脖的带子，外套那种碎纹理没有了。只验证了这一次。
- **换头**：脸，加上照片里的发色和刘海；发长和衣服保持驱动视频的，姿态、光线不动。把照片裁成半身像，Qwen 只改这一帧里的脸、发色、刘海。
  在那条片子上全自动跑通了多次，背影干净，外套干净。

### 为什么没有"只换脸、头发不动"

做过，**做不到稳定，拿掉了。** "只换脸"时 Qwen 经常把驱动视频里原来那张脸原样交回来：参考图和驱动视频是同一个人，
Viggle 随后换成一个陌生人、外套碎成迷彩。共试了 8 次 Qwen（换提示词、换种子、换帧），只有 1 次真把脸换掉，Viggle 也成功。
头发一锁住，Qwen 连脸也一起锁住；换头改了发色和刘海，脸才跟着换过去。

做过的补救也都没用：
- 让视觉模型并排看两张脸问"是不是同一个人"，用来检查脸换没换：8 张手头的参考图判对 7 张，可以用，但检查出来也只是知道失败了，
  换种子、换帧重试三次仍不行（三个帧、三个种子全部失败）。
- 三次不行就退回换头：能保证成片成功，但那就是换头，没必要再留一个名字叫换脸的模式。
- 用脸型网格（MediaPipe 的 468 点）的距离判断脸换没换：真换了和没换的分不开，没用。

想只换脸可以试：脸和发型差别更大的照片，或手写更强的提示词（"原来的脸不能保留，必须看起来是另一个人"这句让一次手工尝试成功过）。这两条没有系统验证过。

检查素材：MCP 的 `inspect_charswap_inputs(project, node_id)`，或后端 `POST /charswap/inspect`，约 10 秒、不占 GPU，报告脸最大最正的一帧、照片里脸占多宽，以及开头是背影、脸太小、片子超过 226 帧等警告。

取脸的帧不填时，后端用 MediaPipe 在 24 个等距帧里找脸最大、最正面的一帧；整条片都没有脸就取中间。

## 复杂场景（2026-10-04 实测，每项一段片、一次）

- **背对镜头、俯视爬行**：视觉模型要同时说清"从哪个方向看"（`VIEW` 行）。早先只写了"一个孩子在爬"，Qwen 就画出正面参考，Viggle 出三角网格；
  提示词里写明"从后上方看、脸不可见、姿势和图 1 相同"后，换成两个不同的人（一女一男）都成功。参考图必须和片子的视角一致。
- **两个人**：只给一张照片会把两个人都换成她，Viggle 随后在一个人转头时出重影。要换两个人，先用 Qwen 一次画好一张双人参考图
  （图 1 = 片中一帧，图 2、图 3 = 两张照片，提示词按左右点名各换成谁），再把这张图原样交给 Viggle（`mode: "reference"`）：两人都换对。
  只换其中一个、另一个原样保留：也成功。
  **节点里已经能做**：在 换人 模式点「选要换的人」，在帧上点出要换的人（第 N 个点对应接入的第 N 张参考图，没点的人保持原样），
  后端把点所在的那一帧取出来，对每个被点的人（裁一条以点为中心的条）和每张照片各问视觉模型一次，写成"右边、距左边约 70%、穿灰色连帽衫的那个人换成图 3 里的人"
  这样的提示词，Qwen 一次画出参考图，再交给 Viggle（`targets`，最多 4 个）。点只在它所在的那一帧上有意义，所以有点时帧固定为点选时的那一秒，换帧会清掉点。
  实测（同一段双人片）：只点右边的男生 → 只有他变了；点两个人配两张照片 → 两人各换对，转头、并肩都稳。
  只能靠左右位置和衣服区分人，没有做人体检测（环境里只有单人的 holistic 模型，没有多人的）；站得很近、前后遮挡的人这样区分不一定准，没测。
  接了多张照片又一个点都没点时，节点和 MCP 都会拒绝运行，因为没法知道谁对应谁。
- **原样**（`mode: "reference"`）：接入的图已经是做好的参考图，原样交给 Viggle，不重画。
- **二次元**：站立转身、男生第一视角牵手回头两段都成功，画风没有被带成写实；自动提示词里仍写 "a photograph"，没有影响。
  远景里脚和鞋沿用了原片（白球鞋变成棕皮鞋），画面切掉的部分没法验证。
- **姿态在片子里变化很大时，参考帧要取中间**：二次元俯视爬行，底部还有第一视角人的交叉双臂（手臂全程原样保留）。
  片子开头低头、结尾抬脸；参考帧取脸最大最正的 4.9 秒时，前半段出现两个姿态叠在一起的重影；取 0.3 秒时新角色从头到尾变成直立跪坐；
  取 2.5 秒（中间）全程干净。所以 换人 模式的自动选帧改成只在片子中间一半里找脸最大的帧（换头不变）；全自动重跑选了 2.58 秒，四帧都干净。只有这一段片子的证据。
- **点选不适合"一个真人加一对手臂"的画面**：两次实测 Qwen 都把原来的人留着、另画了一个新的。这种画面用不点人的全自动。
- 没测：前后遮挡或背对镜头的双人、真人第一视角、多个人同时背身。

## H3 原生换人 + Character-Swap LoRA（推荐的引擎）

换人节点的引擎选 **H3 原生**：整段原片是 `<Video 1>`，新人物的图是 `<Picture 1>`，用 H3 自己的编辑路径渲染，不需要 Qwen 重画参考帧，也不用选帧。
要装 [akatz-ai/MiniMax-H3-Character-Swap-LoRA](https://huggingface.co/akatz-ai/MiniMax-H3-Character-Swap-LoRA)
（`h3_character_swap_pro4500_1000.safetensors`，155 MB，放进 `ComfyUI/models/loras/h3/`；MiniMax H3 社区许可证）。
底模是官方 `ref2va`（`minimax_h3_ref2va_pruned_int8_convrot`），LoRA 强度 1.0，**8 步标准加速**，提示词是一句话，原样发送：

> Replace only **<原片里被换的那个人，带头发和衣服>** in <Video 1> with the character in <Picture 1>. Keep the replacement character's identity, outfit, and art style from <Picture 1>. Preserve the source video's camera, background, lighting, objects, and all other people.

后端的自动做法：视觉模型看原片中间一帧，只回答一句"被换的人是谁、穿什么"（例如 "the girl with long black hair in a navy sailor uniform"）填进去；你也可以在文本框里手写整句覆盖。
**必须说出原片里那个人穿什么**：写成 "the main performer" 时，LoRA 只换了头发和脸，原片的水手服还在身上。后端发给 H3 的提示词一律原样（`build_smart_fallback_h3_prompt` 对手写提示词不再包装，只补空白提示词）。

实测（864×480，8 步，约 105–110 秒；同一个 seed；每条各抽 3–4 帧看）：

| 场景 | 结果 |
| --- | --- |
| 二次元站立转身 → 银白短发少年 | 机位和景别（全身远景）、背景（围栏和城镇）、3.5 秒的挥手、4.5 秒的侧脸都对 |
| 真人俯视背对爬行 → 光头男人 | 背朝镜头、格子衬衫和牛仔裤、起势和爬行都对；赤脚沿用了原片，照片里的靴子没换上 |
| 二次元第一视角手臂 + 爬行 → 青绿短发橙雨衣女孩 | 起始姿势（两手掌撑在头两侧、低头）、机位、底部第一视角的交叉手臂、最后抬头都对 |
| 双人片只点右边的男生 | 只有他换了，左边的女生原样 |
| 双人片点两个人 | 男人全换对；女生头发和脸换了，**衣服还是原片的**（作者页面写着多人没测过） |

**人和动物互换（864×480，8 步，各一次）**：
- 人 → 动物（真人俯视爬行 → 金毛犬）：成功。金毛的毛色和蓬松的尾巴都对，机位、地板和爬行的节奏跟着原片，四条腿也画对了。
- 动物 → 人（棕色小狗小跑 → 短卷发戴眼镜、青绿衬衫裙的女性）：**直接换会出半人半狗**：一颗人头接在狗的身体上，盖着蓝布，狗的四条腿和尾巴还在。新角色的身体形状来自原片的姿态，不是来自照片。
  手写提示词里写明新角色的姿态后成功："Replace only the dog … with the character in <Picture 1>, shown on hands and knees and moving on all fours with the same trotting gait as the dog. Keep … Preserve …"
  女性四肢着地、按狗的步态往前走，最后转头看镜头，青绿衬衫裙、白球鞋、卷发和眼镜都在，背景（草坪和树篱）和机位不变。
  所以骨架差别大的互换，指令里要写出新角色用什么姿态、什么步态运动；骨架相近时（人换人、人换四足动物）不用写。这一条自动写还没做，手写提示词可以。

**不要和 TaoMate 3 步一起用**：同一条站立转身片子，3 步 + LoRA 会在画面两边凭空多出好几个学生。
没配 LoRA 时（六段式提示词、`singularity` 底模）的教训：提示词里写出场景（"混凝土屋顶"）会把原片的围栏和城镇重画掉；写出动作时间线时，视觉模型读错的视角（把侧脸读成背影）会被照着画；只写"同一机位"不写景别，镜头会拉近。
深度控制（Fun ControlNet，强度 1.2）能让挥手跟上，但转身角度和背景是被提示词带偏的，不是控制的问题；这条路没有继续。

H3 原生一次最多 226 帧（约 9.4 秒），更长的片子分段接续（见下面「长片」一节）；没有只换头的模式（换头现在按换人处理），多人同时换衣服不稳。
H3 原生不依赖选帧，姿态在片子里变化大时也稳；原分辨率约 7 分钟，864 小尺寸约 2 分钟，和 Viggle 差不多。

### 动物换人：姿态选项（2026-10-04 实测）

原片主体是四足动物、照片是人时，只写"换掉那只狗"，人会被画成驱动片里狗的骨架：直臂直腿、躯干水平的"人形狗"。节点上的"姿态"三个按钮（H3 引擎，没有点选人时）：自动 / 照原片 / 站立行走。

- 自动：视觉模型看中间帧和照片，主体是动物、照片是人时才加；其他情况不加任何东西。
- 加的内容：让人"站立行走、速度和动物一样、全身可见"，再按原片首帧和末帧读出的身体与头的朝向，写明开头和结尾的站姿。
- 为什么要写起止朝向：只写"站立行走"，起止两个静止段里人会照着参考照片站成正面（原片的狗是侧身、只有头转向镜头）；写明后开头对上，走路段一直是对的。
- 拉远的狗（上方空间足够）也成功，说明"人形狗"不是画面上方空间不够造成的，是骨架。
- 已知的小偏差：结尾身体只是稍微侧过来，没有完全保持侧身，只有头对着镜头；可以接受，没有再调措辞。
- 没做：画面上方放不下站立的人时只拍腿；让用户决定要不要爬。

### 长片：分段接续（2026-10-04 实测一条）

H3 引擎超过 226 帧时不再报错：按 226 帧一段分段渲染，每段取原片对应窗口当 `<Video 1>`，上一段的潜空间尾部接给下一段（视频任务自带的 `chunk_frames`）。

- 实测：10.3 秒（248 帧，半身片正放加倒放，没有切镜）换成卷发眼镜女性，864 小尺寸 8 步，输出 243 帧、2 段；0.5、4、8、9、10 秒五帧里发型、眼镜、青绿衬衫都一致，没看到漂移。
- 只看了五帧，接缝附近（约 8.5 到 9.4 秒）没有逐帧查；只测了一条片子、一个人。
- 分段时不做重启恢复（ComfyUI 历史里只剩最后一段），中途重启会从头再跑。

## 没做到的、没验证的

- **自动写提示词只在这一条片子、一个人身上看到成功**，描述是否总是准确没有大量验证；视觉模型可能把发长、衣服描述错，描述错了提示词就跟着错。
- **没有自动判定成败。** 试过用外套区域的中频能量和闪烁区分：7 个迷彩成片里能抓出 5 个、5 个干净的一个没误判，
  但漏了 2 个，样本又少、阈值是对着这批数据定的，不可靠，没有做进流程。成败要人（或助手）看帧。
- 只在一条片子、一个人身上验证；为什么写明场景和发型就稳，机理不明。
- 手里拿的道具会丢（Viggle 把人整个重画），叙事靠举、递、摔某物的镜头仍走 Ref2VA。
- 一次最多出 124 帧；更长的片按窗口分段，更容易漂。
